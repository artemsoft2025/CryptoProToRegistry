# НАЗНАЧЕНИЕ

Утилита находит программные контейнеры КриптоПро CSP на подключённых дисках
(по умолчанию — только на съёмных носителях) и позволяет скопировать их
в реестр Windows, чтобы работать с электронной подписью без флешки.
Например, случайно выбрано "неэкспортируемый" - в КриптоПро кнопка
"экспортировать" будет неактитвной, тут и поможет эта утилита.


# ТРЕБОВАНИЯ

- Windows 7 / 8 / 8.1 / 10 / 11 (x86 или x64)
- Установленный КриптоПро CSP 4.0 или 5.0
- Права администратора (для записи в HKLM)


# КАК ПОЛЬЗОВАТЬСЯ

1. Вставьте флешку с контейнерами КриптоПро.

2. Запустите CryptoProToRegistry.exe от имени администратора
     (правый клик → «Запуск от имени администратора»).

3. Убедитесь, что в верхней части окна:
  - зелёная строка «КриптоПро CSP: установлен (версия ...)»
  - определён SID текущего пользователя

4. Нажмите «Обновить список».
     Утилита просканирует съёмные носители и покажет найденные контейнеры
     в таблице. Для каждого будет указан диск, имя папки, формат,
     число файлов и полный путь.

5. Выберите нужный контейнер в таблице.

6. Нажмите одну из кнопок:
  - «Добавить в HKLM» — для всех пользователей компьютера
  - «Добавить в HKCU» — только для текущего пользователя
     (либо просто дважды кликните по строке — это то же, что «Добавить в HKLM»).

7. В появившемся окне задайте имя раздела реестра.
     По умолчанию подставляется имя папки контейнера (например, akhbngej.000).
     Можно оставить как есть или ввести понятное имя (например, Ivanov_2026).

8. Дождитесь сообщения «Успех».

9. Если включён чекбокс «Перезапустить службу CSP после копирования»,
     утилита автоматически перезапустит службу cpcsp.
     Если нет — нажмите кнопку «Перезапустить службу CSP» вручную
     или перезагрузите компьютер.


# ЧТО ДЕЛАЕТ УТИЛИТА

Для выбранного контейнера утилита копирует ВСЕ его файлы в раздел реестра:

  HKLM\SOFTWARE\Wow6432Node\Crypto Pro\Settings\Users\{SID}\Keys\<имя>

где {SID} — идентификатор безопасности текущего пользователя,
например S-1-5-21-2083228792-540638026-2747891294-1001.

Каждый файл записывается как параметр типа REG_BINARY,
причём имя параметра сохраняется ВМЕСТЕ с расширением:

  header.key, primary.key, masks.key, name.key, primary2.key, masks2.key

Это ровно та структура, которую создаёт сам КриптоПро CSP 5.0
при выборе «Скопировать контейнер» → «Реестр».


# ПРОВЕРКА РЕЗУЛЬТАТА

1. Откройте КриптоПро CSP:
     Пуск → Все программы → КРИПТО-ПРО → КриптоПро CSP

2. Перейдите на вкладку «Сервис».

3. Нажмите «Просмотреть сертификаты в контейнере».

4. Нажмите «Обзор» — откроется список контейнеров.

5. В колонке «Считыватель» у скопированного контейнера должно быть
     указано «Реестр».


# ОГРАНИЧЕНИЯ

Утилита НЕ РАБОТАЕТ со следующими случаями:

- Аппаратные токены (Рутокен, JaCarta, eToken, ESMART и др.).
    Там закрытый ключ физически не читается через файловую систему,
    и утилита его просто не увидит.

- Контейнеры КриптоПро CSP 5.0 с усиленной защитой.
    Могут не читаться из реестра даже после успешного копирования файлов.

- Ключи, выданные УЦ ФНС (для ИП и директоров ЮЛ).
    Они гарантированно неэкспортируемые, скопировать их нельзя никаким
    способом. Это требование законодательства, а не техническое ограничение.

- Пароль контейнера не переносится.
    Если контейнер защищён паролем, при первом использовании CSP
    запросит его заново.


# ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК

Рядом с утилитой ведётся лог: cryptopro_copy.log
В нём фиксируются все операции: сканирование, копирование, откаты, ошибки.

Если при копировании произошла ошибка, утилита автоматически удалит
частично созданный раздел реестра — «полуконтейнер» не останется.

Для диагностики проблем:

1. Откройте cryptopro_copy.log и найдите последнюю запись [ERROR].
2. Проверьте, установлен ли КриптоПро CSP (зелёная строка в окне).
3. Убедитесь, что запущено от имени администратора.
4. Проверьте, что контейнер на флешке не привязан к носителю
     (см. раздел «ОГРАНИЧЕНИЯ»).


# ЧАСТЫЕ ВОПРОСЫ


В: Почему после копирования КриптоПро CSP не видит контейнер?
О: Перезапустите службу CSP или перезагрузите компьютер.
   CSP читает список контейнеров при инициализации, а не на лету.

В: Копирование прошло успешно, но подпись не ставится. Почему?
О: Скорее всего, контейнер привязан к носителю, либо защищён паролем,
   либо это ключ ФНС. См. раздел «ОГРАНИЧЕНИЯ».

В: Можно ли скопировать контейнер на другую флешку?
О: Зависит от типа ключа. Если он экспортируемый — да, просто скопируйте
   папку. Если неэкспортируемый — нет, не заработает. Проверить можно
   только экспериментально.

В: Что означает {SID} в пути?
О: SID (Security Identifier) — уникальный идентификатор пользователя
   Windows. У каждого пользователя свой SID. Контейнеры КриптоПро
   хранятся отдельно для каждого пользователя.

В: Почему утилита пишет в Wow6432Node?
О: Потому что КриптоПро CSP — 32-битное приложение, даже на 64-битной
   Windows. Его ветки реестра автоматически перенаправляются в
   Wow6432Node. Утилита использует флаг KEY_WOW64_32KEY, чтобы попасть
   именно туда, куда пишет сам CSP.
